## 检查顺序

| 项目 | 操作 | 应当看到的结果 |
| --- | --- | --- |
| 常用入口 | 冷启动打开首页；在桌面长按 FCM Guard 图标 | 首页顶部可直接打开 FCM Diagnostics；桌面菜单出现 FCM 诊断入口，点击进入 Google 的诊断页；返回后没有记录弹窗。菜单外观由 HyperOS 桌面决定。 |
| 一次性诊断授权 | 覆盖安装 3.3.0，按应用内当前用户命令通过可信 ADB 授权；关闭无线调试和 Shizuku，重启后再次核对 | 首页显示应用自身诊断权限来源，能读取时与 Google 诊断一致，磁贴随实际状态变化。HyperOS 拒绝或清除权限时显示未知，不假装已连接。 |
| 诊断权限撤销 | 撤销 DUMP、使用情况权限或拒绝使用情况 AppOp | 旧结果失效；仅在已显式开启且可用时使用 Shizuku，否则保持未知。系统名单不应被修改。 |
| 默认免授权 | 关闭应用内增强检查，再打开诊断和应用检查 | 这些入口仍可使用，不要求 Shizuku；自动 FCM 状态明确显示未知，不能用网络可达代替 Connected。 |
| 授权一致 | 启动 Shizuku，再显式开启增强检查并授权 | 首页和设置区都报告相同的授权、辅助进程状态。已授权但读不到连接信息时，显示具体读取限制，不得称为未授权。 |
| 已连接对照 | Google 诊断显示 Connected 后，返回首页并展开快捷面板，等待一次刷新 | 能读取受支持的 GMS 当前状态时，首页显示 Connected，磁贴点亮；不能读取时保持问号／未知并说明原因。 |
| 断网对照 | 暂时关闭 Wi-Fi 和移动数据，等待 Google 诊断显示未连接，再对照首页和磁贴 | 网络变化先使旧结果失效；读到明确未连接后显示 Disconnected、磁贴灰色断开图标。读不到时仍显示未知，不能把未知冒充断开。测试会暂时中断联网应用，请在方便时进行。 |
| 恢复联网 | 恢复原来的网络及 VPN 设置，再对照 Google 诊断 | 读到新的 Connected 后才重新点亮。磁贴点击可以尝试心跳并进入诊断；不能保证系统接受请求，也不会关闭 GMS。 |
| 授权撤销 | 在 Shizuku 撤销 FCM Guard 授权，再展开磁贴 | 旧的已连接结果失效；上下区域一致显示需要授权。重新授权后可再次查询。 |
| 应用设置 | 选择一个通知应用，依次打开应用、通知、电池设置 | 每个入口都对应所选包名；厂商专用入口不可用时退回同一应用详情，而不是宽泛的应用列表。 |
| 应用状态 | 修改一个目标应用的自启动、通知权限或电池策略，再返回 FCM Guard | 可读取的项目重新检查；未开启自启动优先排列并有红色及文字提示，计数与当前列表一致。系统无限制名单只作为系统导出的参考，不等于所有后台策略均已满足。 |
| 页面状态 | 展开系统名单、切到全部应用，滚动后切换主题 | 列表模式、名单展开状态和滚动位置恢复；返回系统设置仍会重新读取应用状态。 |
| 进程回收 | 正常使用手机，待系统自行回收 FCM Guard；之后下拉或点击磁贴 | 可以重新唤起检查。不能运行期间存在检查空档，应用不应假装持续监控；没有常驻通知或定时唤醒。不要用强行停止来模拟普通回收，两者系统语义不同。 |
| 锁屏推送 | 让另一账号向所选应用发送测试通知，分别在 Wi-Fi、移动网络和日常 VPN 下锁屏观察 | 记录应用、网络、发送/收到时间和是否遗漏。检查通知总开关、类别、应用内静音和账号状态。FCM Connected 只能说明 GMS 连接，不能证明每个应用都已注册或保证通知必达。 |

## 失败时需要的信息

提供对应项目、上述版本信息、Google 诊断当时的 Connected/未连接状态、首页和磁贴的实际状态，以及完整的增强检查错误文字即可。截图可先遮挡账号、通知内容和设备标识。

不要把未知状态改成“已连接”来绕过问题。GMS 更新后如果格式不再支持，应先获取当前状态格式的证据，再修改解析器。
