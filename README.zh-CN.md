# Vigil · HyperOS 应用驻留保活与推送通知全链路诊断

原名 **Push Sentinel / FCM Guard**。保留包名 `com.reed.fcmguard` 与正式签名证书，旧版本可直接无损覆盖升级，原有关注应用、独立诊断授权与偏好设置均完整保留。

[下载最新版 APK](https://github.com/maixuanfeng1/FCMGuard-HyperOS/releases/latest/download/FCMGuard-HyperOS.apk)

---

## 为什么做 Vigil

在 HyperOS 上，一个应用能否及时收到推送、不被系统误杀，往往不只取决于 FCM 通道本身，而是由 **GMS 长连接、自启动策略、系统省电无限制名单、后台任务锁定、通知权限与停止状态** 共同决定。

**Vigil** 将这条完整的保活与通知链路收敛到一个轻量、透明、完全只读的诊断面板中：

- **默认免授权可用**：应用扫描、自启动与通知权限检查、只读系统名单检查、精准设置页直达、Google 诊断入口和快捷磁贴均无需 Shizuku。
- **严格只读、不改系统配置**：不自动写入系统白名单，不静默修改省电策略，不提供任意命令执行接口。
- **零常驻、零后台耗电**：无前台服务、无常驻通知、无后台周期轮询、无唤醒锁或定时唤醒。

## 四大核心体检维度

| 维度 | 检测内容与来源 | 快捷操作与边界说明 |
| --- | --- | --- |
| **① GMS / FCM 实时连接与唤醒** | 读取当前用户 GMS 服务实时连接状态，严格区分 `Connected` / `Disconnected` / `未知`；附带网络可达探测与 GMS 安装状态检查 | 固定按钮直达 Google Play 服务 FCM 诊断页；支持长按桌面图标快捷直达与每分钟限频一次的心跳请求（不以网络探测冒充 GMS 已连接） |
| **② 应用自启动 (`Autostart`)** | 检测关注应用的 HyperOS 自启动状态（已开启 / 未开启 / 部分开启 / 无法读取） | 异常项自动前置排序、红色强调并计入底栏待检查角标；一键直达该应用详情设置页 |
| **③ 省电策略与无限制名单 (`MILLET_NO_RESTRICT_APP` & Doze)** | 只读查询 HyperOS 系统无限制名单及 AOSP 电池优化豁免状态 | 明确区分系统参考名单与完整省电策略；直达该应用独立的电池设置页，不回退到全局应用列表 |
| **④ 后台任务锁定 (`locked_apps`)** | 只读解析 HyperOS `locked_apps` 多用户锁定配置，展示**已锁定 / 未锁定 / 无法读取**，并随锁定变化自动刷新 | 锁定可防止一键清理最近任务时误杀应用；标准 FCM 未锁定时仍可投递，因此锁定状态保持中性提示、不误报异常。内置一键直达手机管家「锁定任务」管理页（不可用时回退操作指引） |

此外，Vigil 还对每个关注应用同步检查 **Android 通知权限 (`POST_NOTIFICATIONS`)** 与 **系统强行停止标志 (`FLAG_STOPPED`)**，并提供单个应用的通知设置直达入口。未声明 FCM/GCM 组件的可启动应用也可加入关注列表进行保活体检。

## 底部三栏界面导览（Material 3）

- **连接（Connection）**：聚合 FCM 实时连接状态卡片、Google 诊断固定入口、可一键跳转的关注应用健康摘要卡片，以及网络探测与限频心跳请求。
- **应用（Apps）**：整屏 Material 3 卡片式列表，展示关注／全部应用的自启动、通知、系统名单、后台任务锁定与 FCM 组件声明；配合顶部固定精简操作栏，以及支持实时搜索与「全部／声明 FCM／已关注」筛选的应用选择器；底栏实时以角标提示待检查的关注应用数；点击任意卡片弹出实时刷新的应用详情面板，支持一键加入／取消关注与直达各项设置。
- **设置（Settings）**：顶部提供「独立诊断权限与快捷磁贴」入口（一键通过 Shizuku 一次性授权、添加系统快捷设置磁贴），下方为事件驱动刷新开关、外观主题（跟随系统／浅色／深色）及默认折叠的「高级选项」（手动 ADB 授权／撤销说明、备用 Shizuku 检查、只读原始名单查看）。

**快捷设置磁贴与桌面快捷方式**：
- 添加快捷磁贴后，仅在下拉控制中心可见时每 5 秒刷新一次当前 GMS 状态（亮起/`Connected`、灰色断开/`Disconnected`、问号/`未知`），收起面板即停止轮询并清除缓存态；点按磁贴尝试限频心跳并打开 Google 诊断。
- 长按桌面 **Vigil** 图标即可直接点击 **「FCM 诊断」** 进入 Google 诊断页，无需任何额外授权。

## 零常驻架构与一次性独立授权

### 零常驻与透明边界

- Vigil 不申请任何前台服务权限，不常驻通知栏，不安排定时唤醒任务。
- 仅在进程自然存活期间监听系统无限制名单（`MILLET_NO_RESTRICT_APP`）、后台任务锁定（`locked_apps`）和默认网络变化；进程被系统回收期间存在检查空档，重新打开应用或下拉磁贴即可恢复。
- 自动连接结论使用 15 秒单调时钟有效期，网络或权限变化立即失效，绝不伪造已连接或断线。
- Vigil 是诊断与直达工具，不承诺全天离线监测或某款第三方应用的通知必达（网络/VPN、GMS 服务、通知渠道及应用自身通道均会影响最终送达）。

### 一次性独立诊断授权（授权后可彻底关闭 Shizuku 与调试）

如需自动读取 GMS 当前连接状态，或在系统限制普通应用直接读取 `locked_apps` 时通过受控只读通道读取，可任选以下一种一次性授权方式：

1. **手机内通过 Shizuku 一次性授权（免电脑）**：通过无线调试启动 Shizuku，回到 Vigil →「设置」点击 **「通过 Shizuku 一次性授权」**。应用按需请求 Shizuku 授权并临时连接辅助进程，就绪后自动弹出权限确认框；辅助进程严格校验实际 Binder 调用 UID 与本应用包名，仅授予固定三项诊断权限（`DUMP`、`PACKAGE_USAGE_STATS` 与 `GET_USAGE_STATS` AppOp），验证生效后自动释放辅助进程并隐藏旧备用模式。
2. **通过电脑 ADB 手动授权**：在「设置 → 高级选项 → 手动 ADB 授权／撤销说明」中复制对应当前用户的三条命令执行即可。

授权生效后，Vigil 直接以**应用自身 UID** 执行固定只读查询，**你可以立即停止 Shizuku，并彻底关闭 USB 调试、无线调试及开发者选项**。详细命令、撤销方法与验证范围见 [一次性诊断授权说明](docs/DIRECT_DIAGNOSTIC_ACCESS.md)。
