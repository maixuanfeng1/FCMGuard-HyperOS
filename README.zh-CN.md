# Vigil · HyperOS 应用驻留保活与推送通知全链路诊断

原名 **Push Sentinel / FCM Guard**，包名为 `com.reed.fcmguard`。从 `v3.5.0` 起，使用现行证书签名的正式版可覆盖升级，保留关注列表、偏好设置和诊断授权。已发布的 `v3.4.1` 使用旧证书，升级到当前版本需卸载后重新安装，应用数据和诊断授权会重置。

[下载最新版 APK](https://github.com/maixuanfeng1/vigil/releases/latest/download/FCMGuard-HyperOS.apk)

---

## 为什么做 Vigil

在 HyperOS 上，一个应用能否及时收到推送、不被系统误杀，往往不只取决于 FCM 通道本身，而是由 **GMS 长连接、自启动策略、系统省电无限制名单、后台任务锁定、通知权限与停止状态** 共同决定。

**Vigil** 将这条完整的保活与通知链路收敛到一个轻量、透明、完全只读的诊断面板中：

- **默认免授权可用**：应用扫描、自启动与通知权限检查、只读系统名单检查、精准设置页直达、Google 诊断入口和快捷磁贴均无需 Shizuku。
- **严格只读、不改系统配置**：不自动写入系统白名单，不静默修改省电策略，不提供任意命令执行接口。
- **零常驻、零后台耗电**：无前台服务、无常驻通知、无后台周期轮询、无唤醒锁或定时唤醒。

## 四大核心体检维度

| 维度 | 检测内容与来源 | 快捷操作与边界说明 |
| --- | --- | --- |
| **① GMS / FCM 实时连接与唤醒** | 读取当前用户 GMS 服务实时连接状态，严格区分 `已连接` / `已断开` / `未知`；附带网络可达探测与 GMS 安装状态检查 | 固定按钮直达 Google Play 服务 FCM 诊断页；支持长按桌面图标快捷直达与每分钟限频一次的心跳尝试（不以网络探测冒充 GMS 已连接） |
| **② 应用自启动 (`Autostart`)** | 检测关注应用的 HyperOS 自启动状态（已开启 / 未开启 / 部分开启 / 未知） | 异常项自动前置排序、红色强调并计入底栏待检查角标；一键直达该应用详情设置页 |
| **③ 省电策略与无限制名单 (`MILLET_NO_RESTRICT_APP` & Doze)** | 只读查询 HyperOS 系统无限制名单及 AOSP 电池优化豁免状态 | 明确区分系统参考名单与完整省电策略；直达该应用独立的电池设置页，不回退到全局应用列表 |
| **④ 后台任务锁定 (`locked_apps`)** | 只读解析 HyperOS `locked_apps` 多用户锁定配置，展示**已锁定 / 未锁定 / 未知**，并随锁定变化自动刷新 | 锁定可防止一键清理最近任务时误杀应用；标准 FCM 未锁定时仍可投递，因此锁定状态保持中性提示、不误报异常。内置一键直达手机管家「任务锁定」管理页（不可用时回退操作指引） |

此外，Vigil 还对每个关注应用同步检查 **Android 通知权限 (`POST_NOTIFICATIONS`)** 与 **系统强行停止标志 (`FLAG_STOPPED`)**，并提供单个应用的通知设置直达入口。未声明 FCM/GCM 组件的可启动应用也可加入关注列表进行保活体检。

## 底部三栏界面导览（Material 3）

- **连接（Connection）**：清晰划分为三张独立 Material 3 卡片——FCM 实时连接状态与 Google 诊断主入口、可一键跳转至应用页的关注应用摘要卡片，以及网络检查与限频心跳尝试。
- **应用（Apps）**：顶部固定「应用检查」控制区（全宽「选择关注应用」主按钮 +「刷新检查／查看全部」次要操作 + 统计概览），以明确分隔线衔接下方整屏 Material 3 卡片列表，紧凑展示自启动、通知权限、无限制名单、后台任务锁定与 FCM 组件声明；支持实时搜索与「全部／声明 FCM／已关注」筛选的应用选择器，底栏角标提示待检查数；点击卡片弹出分为「推送检查／后台检查／系统设置」三区的实时刷新详情面板。
- **设置（Settings）**：拆分为五张独立卡片分区——**诊断权限**（一键「通过 Shizuku 授权」）、**快捷设置**（添加磁贴）、**自动刷新**、**外观**（跟随系统／浅色／深色），以及**关于**（进入独立的「关于 Vigil」页面，支持手动按需从 GitHub Releases 检查更新、直达 GitHub 仓库／发行版／Issues／中英文文档、一键复制版本号与诊断环境信息、分享项目、跳转本应用系统详情、查阅开源许可与第三方组件声明，以及隐私和只读运行边界说明）。手动 ADB 授权与撤销命令统一维护在 [一次性诊断授权说明](docs/DIRECT_DIAGNOSTIC_ACCESS.md)。

**快捷设置磁贴与桌面快捷方式**：
- 添加快捷磁贴后，仅在下拉控制中心可见时每 5 秒刷新一次当前 GMS 状态（亮起/`已连接`、灰色断开/`已断开`、问号/`未知`），收起面板即停止轮询并清除缓存态；点按磁贴尝试限频心跳并打开 Google 诊断。
- 长按桌面 **Vigil** 图标即可直接点击 **「FCM 诊断」** 进入 Google 诊断页，无需任何额外授权。

## 零常驻架构与一次性独立授权

### 零常驻与透明边界

- Vigil 不申请任何前台服务权限，不常驻通知栏，不安排定时唤醒任务。
- 仅在进程自然存活期间监听系统无限制名单（`MILLET_NO_RESTRICT_APP`）、后台任务锁定（`locked_apps`）和默认网络变化；进程被系统回收期间存在检查空档，重新打开应用或下拉磁贴即可恢复。
- 自动连接结论使用 15 秒单调时钟有效期，网络或权限变化立即失效，绝不伪造已连接或断线。
- Vigil 是诊断与直达工具，不承诺全天离线监测或某款第三方应用的通知必达（网络/VPN、GMS 服务、通知渠道及应用自身通道均会影响最终送达）。

### 一次性独立诊断授权（授权后可彻底关闭 Shizuku 与调试）

如需自动读取 GMS 当前连接状态，或在系统限制普通应用直接读取 `locked_apps` 时通过受控只读通道读取，可任选以下一种一次性授权方式：

1. **手机内通过 Shizuku 一次性授权（免电脑）**：通过无线调试启动 Shizuku，回到 Vigil，进入 **「设置 → 诊断权限 → 通过 Shizuku 授权」**。应用按需请求 Shizuku 授权并临时连接辅助进程，就绪后自动弹出权限确认框；辅助进程严格校验实际 Binder 调用 UID 与本应用包名，仅授予固定三项诊断权限（`DUMP`、`PACKAGE_USAGE_STATS` 与 `GET_USAGE_STATS` AppOp），验证生效后自动释放辅助进程并退出临时连接。
2. **通过电脑 ADB 手动授权**：参见 [一次性诊断授权说明](docs/DIRECT_DIAGNOSTIC_ACCESS.md) 中的完整 ADB 授权与撤销命令（主用户编号为 `0`，多用户／工作资料可通过 `adb shell pm list users` 查询）。

授权生效后，Vigil 直接以**应用自身 UID** 执行固定只读查询，**你可以立即停止 Shizuku，并彻底关闭 USB 调试、无线调试及开发者选项**。详细命令、撤销方法与验证范围见 [一次性诊断授权说明](docs/DIRECT_DIAGNOSTIC_ACCESS.md)。

## 构建、验证与许可

- **构建环境**：AGP 9.5.1、官方 SHA-256 校验的 Gradle 9.9.1、JDK 21（Java 17 源码级别）、`compileSdk 37.2`、`targetSdk 37`、`minSdk 24`。
