围绕“检查关注应用的推送条件”重构，默认免 Shizuku，可选开启增强检查。

- 首页固定 FCM 诊断入口，返回后可记录带时间的 Connected／Disconnected 人工观察；网络变化后观察记录失效。
- 自动检查本应用到 Google 推送服务器的网络可达性，明确与 GMS 实际连接状态分开。
- 选择关注应用，包括未检测到 FCM 的应用。显示 FCM/GCM 组件、自启动、系统无限制名单、通知权限、停止标志及 Android 电池优化豁免；已发现问题的应用优先展示。
- 每个应用提供自己的通知、电池和详情设置入口。通知类别、应用内静音／勿扰、后台锁定、实际无限制策略及锁屏收信测试支持独立的人工检查记录，附时间，并在应用更新后失效。
- 磁贴显示时可重新检查；点击尝试限频的重连／心跳请求并打开诊断。不会将请求发出显示为恢复成功，也不会以磁贴亮起冒充持续 Connected。
- 移除强制授权、自动写入 GMS 白名单、“立即修复”和包名编辑。可选 Shizuku 默认关闭，仅提供固定只读名单和带 GMS UID 的网络连接证据，不能确认时显示不可用。
- 无前台服务、常驻通知、周期轮询或定时唤醒。系统名单和网络变化仅在进程可运行时触发刷新，进程冻结／回收期间存在空档。

重要边界：本版本不能持续自动读取 Google Diagnostics 的实际 Connected 字段，也不能保证通知必达。后台锁定、完整通知设置等系统未开放的状态仍需人工确认；网络探测成功、FCM 组件存在、名单成员或网络连接证据均不代表最终收信成功。请在你的 HyperOS 4 真机上对推特／Telegram／Slack 进行锁屏收信验证。
